1. Problem Statement

The Social Security Administration publishes dozens of disability program datasets, but finding the right data, understanding its limitations, and knowing what it cannot answer requires deep institutional knowledge. Analysts and researchers routinely discover that needed data does not exist only after significant research effort, and lack a systematic way to measure the gap between what public data supports and what policy questions demand.

SSA Disability Claims OpenLens solves this by turning dataset discovery into a question-answerable evaluation engine built as a production-quality MCP server.

2. Solution Overview

OpenLens is a deterministic, no-LLM-dependency MCP Dataset Access Server. It evaluates how well available SSA public datasets support answering a natural language question, identifies gaps, and generates structured transparency recommendations.

CapabilityDescription
DiscoverFind SSA disability datasets by keyword, source, or topic
UnderstandPlain-English explanations of dataset contents and limitations

11. Key Design Principles

  • No LLM dependency in the engine — all coverage scoring, intent matching, freshness calculation, and recommendation generation is deterministic pattern matching. Same question always returns the same result.
  • Gap-linked recommendations — every recommendation is linked to the specific information element gap it closes, categorized, prioritized, and justified.
  • Auditability — the engine exposes its reasoning: intent category, matched elements, coverage quality per element, weighted score, and staleness indicators are all returned in the tool response.
  • Separation of concerns — the LLM agent copies the pre-formatted report verbatim; all intelligence lives in the MCP server, not in the agent prompt.
  • Production quality — Pydantic v2 models, full pytest suite with regression tests, Dockerfile, watsonx Orchestrate deployment config, and ADK-compatible agent definition.
